# Відповіді до лабораторної роботи № 6

1. SSE передає текстові події від сервера до клієнта в потоковій HTTP-відповіді. Через WebSocket обидві сторони можуть незалежно надсилати текстові й двійкові фрейми після встановлення з’єднання.
2. Він змушує Go HTTP-сервер відправити буферизовані дані, залишаючи відповідь відкритою для наступних подій.
3. Цикл може залишатися активним після відключення клієнта, доки запис не поверне помилку. Скасування контексту дозволяє одразу завершити очікування події та зупинити таймер.
4. Клієнт надсилає HTTP-запит із `Upgrade: websocket`, `Connection: Upgrade`, ключем і версією. Сервер перевіряє запит і повертає `101 Switching Protocols` із `Sec-WebSocket-Accept`, обчисленим на основі ключа. Після цього сторони обмінюються фреймами WebSocket.
5. Gorilla дозволяє один одночасний виклик операцій звичайного запису на з’єднанні. Hub ставить повідомлення в чергу `send`, звідки їх записує одна горутина `writePump`.
6. Блокуюче читання від клієнта може тривати одночасно з відправленням повідомлень чи Ping. `readPump` та `writePump` виконують ці операції незалежно.
7. Сервер періодично надсилає Ping. Кожен отриманий Pong продовжує дедлайн читання. Коли дедлайн спливає, читання повертає помилку, і з’єднання закривається.
8. Він забезпечує простий прийом текстових подій і автоматичне перепідключення браузера. Для двосторонньої передачі або двійкових даних підходить `WebSocket`, де перепідключення застосунок реалізує самостійно.
